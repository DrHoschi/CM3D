# WD-02 / P0.1 – erster End-to-End-Web-Prototyp

**Stand:** 2026-08-27  
**Status:** IMPLEMENTED – REVIEW/DEVICE TEST REQUIRED  
**Voraussetzung:** WD-01 – FROZEN

## Zielkette

WD-02 setzt ausschließlich den ersten kleinen, durchgängigen und speicherfesten Kern um:

1. Projekt-Shell öffnen
2. 3D-Viewport anzeigen
3. Würfel erzeugen
4. Würfel im Objektbaum anzeigen
5. Würfel im Viewport oder Objektbaum auswählen
6. Transformwerte X/Y/Z, Rotation und Scale verändern
7. Projekt speichern
8. Browser neu laden
9. Projekt laden
10. derselbe Würfel mit derselben `objectId` und denselben fachlichen Daten ist wieder vorhanden

## Implementierter Stand

### Projekt-Shell

- statische ES-Module-Webapp ohne Build-Schritt
- `index.html` + `styles.css`
- Three.js über Import-Map
- getrennte Quellbereiche `model`, `application`, `persistence`, `runtime-three`, `ui`

### Datenmodell

- `format = CM3D_PROJECT`
- `schemaVersion = 0.1.0`
- stabile UUID-basierte `projectId`, `objectId`, `materialId`
- `scene.objects` als Map
- `materials` als Map
- lokaler Transform mit Position, Quaternion, Scale und Pivot
- Längenwerte in Meter

### Würfel

- `primitive.box`
- stabile `objectId`
- Standardgröße 1 m × 1 m × 1 m
- Referenz auf projektweites Standardmaterial

### Three.js-Runtime

- PerspectiveCamera
- OrbitControls
- Grid
- Licht
- Mesh-Erzeugung ausschließlich aus CM3D-Daten
- Runtime-Mapping `CM3D objectId -> Three.js Mesh`
- TransformControls für Verschieben
- Raycast-Auswahl im Viewport

### Objektbaum und Selection

- zentraler Selection-State über `objectId`
- Auswahl aus Objektbaum und Viewport
- Inspector und TransformControls folgen derselben `activeObjectId`
- Selection wird nicht gespeichert

### Inspector

- Name
- Position X/Y/Z in Meter
- Rotation X/Y/Z in Grad als UI-Werte
- persistierte Rotation als Quaternion
- Scale X/Y/Z
- sichtbare `objectId` zur Testkontrolle

### Save/Load

- validierte JSON-Serialisierung derselben CM3D-Projektstruktur
- Browser-Persistenz über `localStorage` als technischer WD-02-Ablageort
- `format` und `schemaVersion` werden validiert
- IDs, Materialreferenzen und Transformwerte werden validiert
- aktiver Projektzustand wird erst nach erfolgreichem Parse/Validate ersetzt
- Selection startet nach Load leer
- Three.js-Meshes werden beim Load neu aus dem Datenmodell aufgebaut

## Manueller Abnahmetest

1. Anwendung öffnen.
2. `Würfel` drücken.
3. `objectId` im Inspector notieren.
4. Position X z. B. auf `2.5` setzen.
5. Rotation Y z. B. auf `30` setzen.
6. Scale z. B. X = `1.5` setzen.
7. `Speichern` drücken.
8. Browserseite vollständig neu laden.
9. `Laden` drücken.
10. Würfel im Objektbaum auswählen.
11. Prüfen:
   - `objectId` entspricht exakt der vorher notierten ID.
   - Position X = 2.5 m.
   - Rotation Y entspricht 30° innerhalb üblicher Quaternion/Euler-Rundung.
   - Scale X = 1.5.
   - Würfel erscheint an derselben sichtbaren Stelle/Orientierung/Größe.
12. Würfel im Viewport anklicken und prüfen, dass Objektbaum und Inspector dieselbe Auswahl zeigen.

## Bekannte Grenze – Iconset

Das V3-Iconpaket ist fachlich dokumentiert, die 148 eigentlichen SVG-Dateien liegen derzeit jedoch nicht als Binär-/SVG-Bestand im GitHub-Repository. Deshalb verwendet WD-02 vorläufig Textbuttons.

Dies ist kein Architekturblocker: Sobald die SVG-Dateien im Repository verfügbar sind, können die Buttons auf die verbindlichen Icons umgestellt werden, ohne Datenmodell, Runtime oder Save/Load zu verändern.

## Nicht-Scope

- keine vollständigen 89 Master-Funktionen
- kein vollständiges Undo/Redo-UI
- keine komplexe Hierarchiebearbeitung
- keine Sketch-/Assembly-Implementierung
- keine Im-/Exporter
- keine Materialbibliothek
- keine komplexe Dateiverwaltung
- kein Kollaborations-/Onlinebetrieb

## Exit-Regel

WD-02 wird erst als PASS/FROZEN gewertet, wenn der manuelle End-to-End-Test einschließlich echtem Browser-Reload erfolgreich durchgeführt wurde. Bis dahin bleibt der Implementierungsstand auf einem separaten Branch und wird nicht als finaler WD-02-Stand nach `main` eingefroren.
