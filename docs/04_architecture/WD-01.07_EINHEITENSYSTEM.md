# WD-01.07 – Internes Einheitensystem und mm/cm/m/km-Anzeige

**Stand:** 2026-08-27  
**Status:** DECIDED  
**Teil von:** WD-01 – Technisches Fundament & Datenmodell

## Grundentscheidung

CM3D verwendet **Meter (`m`) als einzige kanonische interne Längeneinheit** für Geometrie, Transform-Positionen, Pivotwerte, Maße und sonstige räumliche Längenwerte.

Die Einheiten `mm`, `cm`, `m` und `km` sind ausschließlich Eingabe-/Anzeigeeinheiten. Ein Wechsel der Anzeigeeinheit verändert niemals die intern gespeicherte Geometrie oder Position eines Objekts.

Damit gilt:

- 1 internes Längeneinheit = 1 Meter
- 1 mm = 0.001 m
- 1 cm = 0.01 m
- 1 m = 1 m
- 1 km = 1000 m

## Warum Meter als interne Einheit

Meter ist für CM3D der geeignetste gemeinsame Nenner, weil:

1. Three.js keine eigene physische Einheit erzwingt und sich Meter direkt als 1:1-Konvention verwenden lässt.
2. moderne 3D-Austauschformate und technische Workflows häufig mit Meter als neutraler Basiseinheit arbeiten.
3. kleine Bauteile weiterhin präzise als Dezimalwerte darstellbar sind, z. B. 1 mm = 0.001 m.
4. große Anlagen nicht unnötig mit sehr großen Millimeterwerten arbeiten müssen.
5. ein Wechsel der Benutzeranzeige zwischen mm/cm/m/km nur eine Formatierungs- und Eingabefrage bleibt.

## Persistenzregel

Alle räumlichen Werte in der `.cm3d`-Datei werden in Meter gespeichert, sofern für ein Feld nicht ausdrücklich eine andere physikalische Größe definiert ist.

Beispiele:

```json
{
  "position": { "x": 1.25, "y": 0, "z": 0 },
  "pivot": { "x": 0, "y": 0.05, "z": 0 },
  "data": {
    "size": { "x": 0.1, "y": 0.2, "z": 0.3 }
  }
}
```

Bedeutung:

- `position.x = 1.25` → 1.25 m
- `pivot.y = 0.05` → 5 cm
- `size.x = 0.1` → 100 mm

Die gespeicherten Zahlen tragen nicht an jeder Stelle zusätzlich einen Einheitstext. Die Einheit ist durch das CM3D-Schema eindeutig festgelegt.

## Projekteinstellung für Anzeigeeinheit

Das Projekt besitzt eine persistierbare bevorzugte Anzeigeeinheit:

```json
{
  "settings": {
    "units": {
      "lengthDisplayUnit": "mm"
    }
  }
}
```

Zulässige Kernwerte:

- `mm`
- `cm`
- `m`
- `km`

Diese Einstellung beeinflusst:

- Inspector-Anzeige
- numerische Eingabefelder
- Statusleiste
- Raster-/Snap-Anzeige
- Bemaßungsdarstellung

Sie beeinflusst **nicht** den intern gespeicherten metrischen Zahlenwert.

## Eingaberegel

Benutzereingaben werden beim Übernehmen unmittelbar in Meter normalisiert.

Beispiele bei Anzeigeeinheit `mm`:

- Eingabe `250` → intern `0.25`
- Eingabe `1` → intern `0.001`
- Eingabe `1250.5` → intern `1.2505`

Später darf CM3D auch explizite Einheiten in Eingabefeldern akzeptieren, z. B. `2.5 m` oder `35 cm`. Solche Komfortfunktionen ändern die interne Einheit nicht.

## Anzeigeregel

Intern gespeicherte Meterwerte werden erst für die UI in die gewünschte Einheit umgerechnet.

Beispiel für intern `1.25 m`:

- `1250 mm`
- `125 cm`
- `1.25 m`
- `0.00125 km`

Die UI darf Werte sinnvoll runden und formatieren. Diese Rundung ist ausschließlich Darstellung und darf beim bloßen Anzeigen keinen Datenverlust verursachen.

## Einheit wechseln

Ein Wechsel von `mm` auf `m` oder `km` ist **keine Skalierungsoperation**.

Beispiel:

Ein Objekt mit intern `position.x = 2` bleibt bei jedem Einheitenwechsel physisch bei 2 m.

Nur die Darstellung wechselt beispielsweise von:

- `2000 mm`
- zu `2 m`

CM3D darf beim Wechsel der Anzeigeeinheit niemals alle Objektwerte multiplizieren oder dividieren und neu abspeichern.

## Große Anlagen und kleine Bauteile

CM3D soll gleichzeitig kleine technische Details und große Anlagen abbilden können.

Typische Größenbereiche:

- 1 mm → `0.001 m`
- 10 mm → `0.01 m`
- 1 m → `1 m`
- 100 m → `100 m`
- 1 km → `1000 m`
- 10 km → `10000 m`

Mit JavaScript-Double-Precision sind diese Größen für den vorgesehenen technischen Designer grundsätzlich problemlos gemeinsam darstellbar.

Die schwierigere Grenze entsteht nicht im gespeicherten Datenmodell, sondern später bei GPU-/Viewport-Präzision sehr weit vom Weltursprung entfernt. Deshalb wird folgende Architekturregel vorbereitet:

**Große Weltkoordinaten dürfen später durch Viewport-Techniken wie Floating Origin / Origin Rebasing oder lokale Render-Ursprünge behandelt werden, ohne die kanonischen CM3D-Projektdaten umzuschreiben.**

Eine solche Runtime-Technik ist nicht Teil von WD-02, darf aber das Datenmodell später nicht verändern müssen.

## Three.js-Regel

Für die Three.js-Runtime gilt dieselbe logische Skala:

**1 Three.js-Unit = 1 Meter.**

Damit ist keine zusätzliche globale Render-Skalierung zwischen CM3D-Datenmodell und Three.js erforderlich.

Ein Objekt mit:

```json
"position": { "x": 2, "y": 0, "z": 0 }
```

wird in der Three.js-Runtime grundsätzlich ebenfalls bei X = 2 positioniert.

## Skalierung ist keine Maßeinheit

Das in WD-01.05 definierte `scale` bleibt dimensionslos.

Beispiel:

```json
"scale": { "x": 2, "y": 1, "z": 1 }
```

bedeutet eine Verdopplung entlang X und nicht „2 Meter“.

Physische Abmessungen parametrischer Primitive gehören in deren `data`-Block und werden dort in Meter gespeichert.

## Winkel und weitere Größen

WD-01.07 entscheidet ausschließlich die Längeneinheit.

Rotation bleibt gemäß WD-01.05 intern als Quaternion gespeichert. Euler-Anzeigen erfolgen in Grad, ohne dass Grad eine geometrische Längeneinheit ist.

Weitere physikalische Größen wie Fläche, Volumen, Masse oder elektrische Größen werden erst eingeführt, wenn die zugehörigen Funktionen tatsächlich benötigt werden.

## Raster und Snap

Raster- und Snap-Abstände werden intern ebenfalls in Meter gespeichert.

Beispiel:

```json
{
  "gridStep": 0.01,
  "snapStep": 0.01
}
```

entspricht 10 mm.

Bei Anzeigeeinheit `mm` kann die UI daraus `10 mm` anzeigen; bei `cm` entsprechend `1 cm`.

## Import-/Export-Regel

Externe Formate dürfen andere Einheitensysteme besitzen oder Einheitinformationen mitbringen.

Beim Import muss deshalb eine explizite Konvertierung in die interne CM3D-Metereinheit erfolgen. Beim Export wird aus Meter in die vom Zielformat geforderte bzw. gewählte Einheit konvertiert.

Der Import-/Export-Block entscheidet später die formatspezifischen Details; die interne CM3D-Einheit bleibt davon unberührt.

## Numerische Genauigkeit

Die in WD-01.05 festgelegte Double-Precision-Regel bleibt bestehen.

Insbesondere werden Millimeterwerte nicht auf drei Dezimalstellen in Metern begrenzt. Werte wie `0.001234567` m bleiben intern zulässig, sofern die jeweilige Funktion dies fachlich benötigt.

Darstellung und Eingabepräzision dürfen kontextabhängig sein, ohne die gespeicherte Präzision zu reduzieren.

## WD-02/P0.1-Anwendung

WD-02 muss mindestens nachweisen:

1. Projektanzeigeeinheit `mm` auswählen.
2. Würfelgröße z. B. `100 mm` eingeben.
3. intern wird `0.1 m` gespeichert.
4. Position z. B. `2500 mm` eingeben.
5. intern wird `2.5 m` gespeichert.
6. Projekt speichern und Browser neu laden.
7. nach dem Laden bleiben die internen Meterwerte identisch.
8. Umschalten der Anzeige auf `m` zeigt `0.1 m` bzw. `2.5 m`, ohne Geometrie oder Position zu verändern.

## Abnahmekriterium WD-01.07

WD-01.07 ist erfüllt, wenn:

- jede Längeneingabe eindeutig in Meter normalisiert werden kann,
- jede gespeicherte Länge eindeutig wieder in mm/cm/m/km angezeigt werden kann,
- ein Wechsel der Anzeigeeinheit keinerlei physische Skalierung des Projekts verursacht,
- kleine Bauteile und große Anlagen dasselbe kanonische Einheitensystem verwenden,
- Three.js ohne zusätzliche globale Einheitenskalierung aus den CM3D-Daten aufgebaut werden kann.
