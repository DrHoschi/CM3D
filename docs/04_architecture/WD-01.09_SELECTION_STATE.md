# WD-01.09 – Selection-State

**Status:** DECIDED

## Grundentscheidung

Selection ist ein reiner Runtime-/UI-Zustand und wird über stabile CM3D-`objectId`s geführt. Die Auswahl ist nicht Bestandteil der fachlichen SceneObject-Daten und wird standardmäßig nicht in der `.cm3d`-Projektdatei persistiert.

Damit gilt:

- Auswahl bezieht sich immer auf `objectId`
- Three.js-UUIDs dürfen nicht als Selection-Identität verwendet werden
- Auswahl beeinflusst keine fachliche Objektidentität
- Save/Load muss unabhängig vom aktuellen Selection-State funktionieren

## Runtime-Modell

Für WD-02 wird mindestens folgender Selection-State vorgesehen:

```text
selectedObjectIds: objectId[]
activeObjectId: objectId | null
hoveredObjectId: objectId | null
```

### selectedObjectIds

Enthält die aktuell ausgewählten SceneObjects. Bereits in WD-02 darf das Datenmodell Mehrfachauswahl vorbereiten, auch wenn die erste UI zunächst nur Einzelauswahl verwendet.

### activeObjectId

Bezeichnet das primäre aktive Objekt innerhalb der Auswahl. Dieses Objekt ist die maßgebliche Referenz für Inspector, Transform-Gizmo und kontextbezogene Aktionen.

Bei Einzelauswahl gilt:

```text
selectedObjectIds = [id]
activeObjectId = id
```

Bei leerer Auswahl:

```text
selectedObjectIds = []
activeObjectId = null
```

### hoveredObjectId

Ist ausschließlich temporärer UI-/Pointer-Zustand. Dieser Wert wird niemals persistiert.

## Persistenzregel

Die `.cm3d`-Projektdatei speichert standardmäßig weder:

- `selectedObjectIds`
- `activeObjectId`
- `hoveredObjectId`
- aktive Transform-Gizmo-Achse
- temporäre Marquee-/Box-Selection
- Fokuszustände von Objektbaum oder Inspector

Ein Projekt darf also mit exakt demselben fachlichen Inhalt geladen werden, unabhängig davon, welches Objekt beim letzten Speichern markiert war.

Falls später ein Workspace-/Session-Restore gewünscht ist, muss dieser getrennt von der fachlichen `.cm3d`-Projektdatei gespeichert werden.

## Auswahlquelle

Viewport und Objektbaum dürfen beide Auswahl auslösen, müssen aber denselben zentralen Selection-State aktualisieren.

Es darf nicht mehrere voneinander unabhängige Wahrheiten geben wie:

- Objektbaum sagt Objekt A ist ausgewählt
- Viewport sagt Objekt B ist ausgewählt
- Inspector zeigt Objekt C

Der zentrale Selection-State ist die alleinige Runtime-Wahrheit für Auswahl.

## Synchronisationsregel

Jede Selection-Änderung löst eine einheitliche Aktualisierung aus:

1. neue `selectedObjectIds` bestimmen
2. `activeObjectId` bestimmen
3. ungültige/nicht existente IDs herausfiltern
4. Objektbaum aktualisieren
5. Viewport-Highlight aktualisieren
6. Inspector auf `activeObjectId` aktualisieren
7. Transform-Gizmo auf `activeObjectId` ausrichten oder ausblenden

## Löschregel

Wird ein ausgewähltes Objekt gelöscht, muss seine `objectId` sofort aus dem Selection-State entfernt werden.

Wenn `activeObjectId` gelöscht wird:

- bei verbleibender Mehrfachauswahl wird ein anderes gültiges ausgewähltes Objekt aktiv
- andernfalls wird `activeObjectId = null`

Der Selection-State darf niemals dauerhaft auf eine nicht existierende `objectId` zeigen.

## Ladeverhalten

Beim normalen Laden einer `.cm3d`-Datei startet der Selection-State leer:

```text
selectedObjectIds = []
activeObjectId = null
hoveredObjectId = null
```

Danach kann die UI eine Auswahl erst wieder durch Benutzerinteraktion erzeugen.

## Three.js-Regel

Ein Three.js-Mesh darf die zugehörige CM3D-`objectId` als Runtime-Mapping tragen, damit ein Raycast-/Pointer-Hit zurück zum fachlichen SceneObject aufgelöst werden kann.

Die Kette lautet:

```text
Three.js Hit -> CM3D objectId -> Selection-State -> SceneObject
```

Nicht zulässig ist:

```text
Three.js UUID -> dauerhafte fachliche Auswahlidentität
```

## Gesperrte/unsichtbare Objekte

`visible = false` bedeutet nicht automatisch, dass eine vorhandene Auswahl fachlich ungültig ist; die konkrete UI kann die Auswahl jedoch aufheben oder verdecken. `locked = true` darf Auswahl zulassen, verhindert aber editierende Transform-/Modellierungsaktionen, sofern die jeweilige Funktion nichts anderes festlegt.

Damit bleiben Sichtbarkeit, Sperre und Auswahl getrennte Zustände.

## WD-02/P0.1-Anwendung

WD-02 muss mindestens nachweisen:

1. Würfel im Viewport anklicken -> seine `objectId` wird ausgewählt.
2. derselbe Würfel wird im Objektbaum als ausgewählt markiert.
3. Inspector zeigt den Würfel über dieselbe `activeObjectId`.
4. Klick auf leeren Viewport hebt Auswahl auf.
5. Projekt speichern, Browser neu laden und Projekt laden -> SceneObject bleibt erhalten, Selection-State startet leer.
6. erneute Auswahl funktioniert mit derselben gespeicherten `objectId`.

## Abnahmekriterium WD-01.09

WD-01.09 ist erfüllt, wenn Auswahl ausschließlich über gültige CM3D-`objectId`s gesteuert wird, Viewport/Objektbaum/Inspector denselben zentralen Zustand verwenden und Save/Load ohne persistierte Auswahl vollständig reproduzierbar funktioniert.
